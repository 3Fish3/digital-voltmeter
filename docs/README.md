## 更新方式

1. **目标**：保持出发点与来源稳定。目标发生实质调整时，先记录变更原因和确认结果，再同步目标、进度与受影响的设计内容。
2. **进度**：每次推进更新阶段状态与对应问题行，追加日期、动作、验证结果。问题关闭时保留日期与证据；历史结果注明当时范围，与本次重跑分开记录。
3. **设计**：每次电路或设计方案更新后，完整重写`design-report.md`为当时唯一、可独立阅读的现行报告。同步版本/更新时间、接口、参数、预算、依据、网络附录与CSV；删除失效接法和数值，避免在正文追加相互冲突的旧方案。仅文档合并不升级硬件版本。
4. **历史**：设计改动的原因、旧方案取舍与问题处理放在`progress.md`；旧版全文通过Git历史追溯。停止维护按版本平铺或逐级补充的旧设计报告。
5. **验证**：更新后核对文档与原理图/蓝图/CSV、预算脚本的一致性并检查本地链接。设计变更需重跑受影响的工程检查；原始导出与独立清单按其来源保留，缺失项记录在进度中。
